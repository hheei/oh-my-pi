# omp-mctx is a three-way merge, not a rename

The package starts as a copy of hepi `pi-mctx`, then replaces the host layer with cortexkit `packages/pi-plugin@0.40.1` (`omp.extensions`, `getPluginSettings`, `@oh-my-pi/pi-coding-agent`), then cherry-picks every applicable `src/core` change from `7dcd2e57` through `v0.40.1` (`a239835e`), including memory, embedding, and dreamer fixes. Dreamer and sidekick stay disabled in settings. `ctx_memory` is unregistered only after that alignment. A verbatim Pi copy cannot load: it imports `@earendil-works/pi-coding-agent` and `@hheei/pi-ext-core`, uses `/ext-settings`, and mutates `message_end` snapshots that OMP does not write back. Forking live 0.40.1 and grafting HEPI deltas was rejected so fail-closed, latch, and the HEPI core tree remain the starting point. hepi-mono `pi-mctx` is frozen; OMP work does not edit it.
